04

SQL Agent with Tool Use

Reason step-by-step over database tools
▶ think → act → observe → repeat
Doesn't write one query and hope. The agent is given three narrow tools — list tables, inspect schema, run query — and decides at each step which to call, reading the result before deciding its next move.
WORKFLOW
1

Think

The LLM is given the question and a list of available tools, with no schema up front. It decides what it needs to know first.

2

Act

It calls exactly one tool — list_tables, get_schema(table), or run_query(sql) — never more than one per step.

3

Observe

The tool's output — a table list, a schema, a query result, or an error — is appended to the conversation as an observation.

4

Repeat or answer

The LLM re-reads everything so far and either takes another action or, once it has enough, stops and answers in plain English.

VS REFERENCE
  • Reference (and Experiment 1) generates a full query in one shot, against tables chosen by embedding retrieval. This agent doesn't know the schema at all until it asks — schema access is a tool call, not a precondition.
  • Failure handling isn't a separate repair function — a query error is just another observation the same loop reasons over, no special-cased retry path.
  • The trace is inherently multi-step and inspectable: every Thought/Action/Observation is a discrete, loggable turn, not two LLM calls hidden inside one function.
